# Granskning av PR 1: DeepL-SDK

Granskad 2026-11-11. PR: <https://github.com/yeager/po-translate/pull/1>.

## Resultat

Åtgärdad i PR:ns huvudgren den 2026-11-11, commit
`5d3b2306ae08f68a0cc5c7aca8e4fd37bab0afb5`. GitHub bekräftar att PR:n är
sammanfogbar, men den har ännu inga CI-kontroller eller efterföljande
upstream-granskning.

1. `po_translate.py` importerade paketet `deepl`, men paketet saknades från
   projektets Python-metadata i `pyproject.toml`. En ren `pip install .`
   installerar därför inte beroendet. Att köra `--service deepl` ger en
   ohanterad `ModuleNotFoundError` innan programmet kan ge ett användbart fel.
   RPM-specifikationen har endast en rekommendation, vilket inte avhjälper
   övriga installationssätt.
2. Den borttagna tjänsten `deepl-free` fanns kvar i både den installerade
   och den genererade man-sidan, inklusive ett körbart exempel. Dokumentationen
   motsade därmed programmets nya argumentlista.

Fixen lägger till `deepl` som paketberoende, gör saknat SDK till ett
begripligt fel, bevarar tidigare språkhantering för norska och portugisiska,
uppdaterar RPM-beroendet samt synkar hjälpen, man-sidorna och
översättningskällfilerna. Debianpaketets byggskript deklarerar också
`python3-deepl`.

## Verifiering

- `python3 -m py_compile po_translate.py`: godkänd.
- 23 tester: godkända.
- Ren lokal paketinstallation: `deepl` installeras.
- Körning utan installerat SDK: begripligt fel, ingen traceback.
- Debianbyggskriptets syntax och beroende: godkända. Själva `.deb`-bygget
  kunde inte köras eftersom granskningsmiljön saknar `dpkg-deb`.
- `git diff --check`: godkänd.
- Gitleaks: inga hemligheter hittades.
- Projektets befintliga testfil använder pytest-stil, men pytest är inte
  installerat i granskningsmiljön; inga automatiska projekttester kördes.

Fixen är pushad till PR-huvudgrenen.
